### Часть 1. Как создать абсолютно неизменяемый класс (5 правил)

На собеседовании недостаточно сказать: _"Сделать поля `private final` и не писать сеттеры"_. Это ответ джуниора, который ломается на первой же изменяемой коллекции.

Вот 5 строгих правил создания Immutable-класса:

1. **Класс должен быть `final`.** Чтобы никто не смог унаследоваться от него, переопределить методы (геттеры) и вернуть из них изменяемые данные.
    
2. **Все поля должны быть `private` и `final`.** Состояние задается только один раз — в конструкторе.
    
3. **Никаких сеттеров (методов, меняющих состояние).** Если нужно изменить объект, метод должен возвращать **новый** объект с измененными данными (как работает `String.replace()`).
    
4. **Глубокое копирование в конструкторе (Защита на входе).** Если ты передаешь в конструктор изменяемый объект (например, `List` или `Date`), ты не должен сохранять ссылку на него! Иначе кто-то изменит этот список извне, и твой "неизменяемый" объект изменится.
    
5. **Глубокое копирование в геттерах (Защита на выходе).** Если кто-то вызывает геттер для поля `List`, ты должен вернуть **копию** этого списка, а не оригинал.
    

**Пример "Senior-уровня":**

Java

```
import java.util.ArrayList;
import java.util.List;

// 1. Класс final
public final class ImmutableStudent {
    // 2. Поля private final
    private final String name; // String и так immutable, с ним проблем нет
    private final List<String> skills; // А вот List - изменяемый!

    public ImmutableStudent(String name, List<String> skills) {
        this.name = name;
        // 4. Глубокое копирование на входе! 
        // Не пишем this.skills = skills;
        this.skills = new ArrayList<>(skills); 
        // Или в современных версиях: this.skills = List.copyOf(skills);
    }

    public String getName() {
        return name;
    }

    public List<String> getSkills() {
        // 5. Глубокое копирование (или неизменяемая обертка) на выходе!
        // Не возвращаем ссылку на оригинальный this.skills;
        return List.copyOf(skills); 
    }
}
```

> **Эпоха Java 14+:** Сегодня тебе больше не нужно писать всю эту "лапшу" руками. Появились **Records**. Если ты напишешь `public record Student(String name, List<String> skills) {}`, компилятор сам сделает класс `final`, а поля неизменяемыми. (Но за копированием изменяемых объектов внутри коллекций всё равно придется следить самому).
