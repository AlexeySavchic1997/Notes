Тема времени — это, пожалуй, источник самого большого количества багов на проде и самая частая причина ночных звонков дежурному разработчику, когда где-нибудь в мире происходит переход на летнее/зимнее время.

На собеседовании твой ответ должен начинаться с разрушения главного мифа, в который верят 90% разработчиков.

### 1. Главный миф: Как это хранится на диске

**Миф:** `TIMESTAMPTZ` (Timestamp with time zone) сохраняет часовой пояс (например, `+03:00` или `Europe/Moscow`) прямо в базу данных вместе со временем. **Правда:** **Ни один из этих типов не сохраняет часовой пояс на жесткий диск!**

И `TIMESTAMP`, и `TIMESTAMPTZ` занимают ровно **8 байт** физического места. И тот, и другой хранят просто огромное число (количество микросекунд с 1 января 2000 года в формате UTC).

Вся разница между ними заключается только в том, **как база данных реагирует на входящие и исходящие данные** в зависимости от настроек твоего текущего подключения (сессии).

### 2. TIMESTAMP (Without Time Zone) — "Настенные часы"

Этот тип полностью игнорирует часовые пояса. Он хранит ровно то "лицо часов", которое ты ему передал.

- **Как работает:** Если ты вставишь `2024-10-01 15:00:00`, база запишет `15:00`. Если твой сервер в Токио запросит эти данные, он получит `15:00`. Если сервер в Нью-Йорке запросит их, он тоже получит `15:00`.
    
- **В чем проблема:** Это не фиксированная точка на временной шкале Вселенной. Для Токио и Нью-Йорка эти `15:00` означают абсолютно разные физические моменты времени.
    
- **Когда использовать:** Только для абстрактных локальных событий. Например, "Новый год наступает 31 декабря в 23:59:59". (Это происходит в разное время физически, но на часах у всех одинаковое время).
    

### 3. TIMESTAMPTZ (With Time Zone) — "Абсолютное время" — Выбор Senior'а

Это стандарт индустрии. Он фиксирует точный момент времени в истории Вселенной.

- **Как работает при записи (INSERT):** База смотрит на время, которое ты прислал. Если ты прислал его с часовым поясом (`2024-10-01 15:00:00+03`), база на лету конвертирует его в UTC (отнимет 3 часа) и запишет на диск `12:00:00`. Если ты пришлешь без пояса, база возьмет часовой пояс твоего подключения (по дефолту) и сделает то же самое.
    
- **Как работает при чтении (SELECT):** База берет `12:00:00` (UTC) с диска, смотрит на часовой пояс твоего текущего соединения (например, `TimeZone = 'Asia/Tokyo'`) и **на лету прибавляет 9 часов**, отдавая тебе `21:00:00`.
    
- **Когда использовать:** В 99.9% случаев. Дата регистрации пользователя, время транзакции, логи, удаление — всё это должно быть `TIMESTAMPTZ`.
    

> **Правило Архитектора:** В базе данных (в `postgresql.conf`) параметр `timezone` **всегда** должен быть установлен в `UTC`. Серверы приложений (JVM) тоже должны работать в UTC. Любые конвертации в локальное время юзера (Москвы, Лондона) должны происходить только на самом клиенте (в браузере / мобилке).

### 4. Как маппить это на Java (Spring / Hibernate)

Начиная с Java 8 (JSR-310), мы навсегда забыли про старые и кривые классы `java.util.Date` и `java.sql.Timestamp`. Мы используем только пакет `java.time`.

Вот идеальный маппинг в Entity:

**Для TIMESTAMP (Без зоны):** Используем `LocalDateTime`. Он описывает дату и время без привязки к географии.

Java

```
@Column(name = "local_event_time")
private LocalDateTime localEventTime;
```

**Для TIMESTAMPTZ (С зоной):** Здесь есть два варианта, но стандарт де-факто — это **`Instant`**. `Instant` в Java — это точка на временной шкале (количество наносекунд с 1970 года в UTC). Он идеально ложится на семантику `TIMESTAMPTZ`. Hibernate "из коробки" понимает это и правильно передает в Postgres.

Java

```
@Column(name = "created_at", columnDefinition = "TIMESTAMP WITH TIME ZONE")
private Instant createdAt;
```

_(Второй вариант — `OffsetDateTime`, но `Instant` предпочтительнее, так как он гарантированно хранит время в UTC и не тянет за собой лишнюю логику смещений в бизнес-слое)._

**Как это работает в коде:** В сервисе ты просто пишешь `entity.setCreatedAt(Instant.now());` — и спишь спокойно. Приложение отдаст фронтенду JSON в формате `2024-10-01T12:00:00Z` (буква Z в конце означает Zulu time, он же UTC), а браузер пользователя сам с помощью JavaScript превратит это в его локальное время.
