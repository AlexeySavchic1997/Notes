Абсолютно верно. Ответ «это база данных временных рядов» — это уровень стажера. На собеседовании от Senior Java разработчика ждут понимания того, **как архитектура Prometheus влияет на архитектуру твоего Java-приложения** и как ты будешь искать баги с его помощью.

DevOps-инженеры настраивают сервера, но именно ты (разработчик) поставляешь им данные. Если ты поставляешь мусор или не понимаешь, как эти данные читаются, мониторинг будет бесполезен.

Вот 4 вещи, которые Senior Java разработчик обязан знать про Prometheus.

### 1. Математика счетчиков и функция `rate()` (Сброс при рестарте)

Ты создал счетчик в Java: `registry.counter("orders").increment()`. На дашборде он показывает `1500` заказов. Вдруг под с приложением падает из-за нехватки памяти (OOM) и Kubernetes его перезапускает. Что произойдет со счетчиком в Java? **Он сбросится в 0.**

Если ты просто выведешь значение этого счетчика на график в Grafana, ты увидишь линию, которая росла до 1500, потом рухнула в 0 и снова начала расти. Для бизнеса этот график бесполезен (он не показывает, сколько всего заказов было за день).

**Что должен знать разработчик:** В Prometheus никогда не смотрят на "сырые" значения счетчиков. Используют функцию **`rate()`** или **`increase()`** в языке запросов PromQL.

Фрагмент кода

```PromQL
rate(orders_total[5m])
```

_Магия:_ Prometheus знает, что счетчики могут только расти. Если он видит, что значение было 1500, а при следующем сборе стало 5, он понимает: _"Ага, был рестарт пода!"_. Он математически склеивает эти два отрезка, игнорирует падение в ноль и показывает тебе реальную скорость поступления заказов (например, 10 заказов в секунду), даже если приложение перезапускалось 5 раз за час.

### 2. Service Discovery (Как Prometheus находит твои поды)

Раз Prometheus работает по Pull-модели (сам ходит за метриками), как он узнает IP-адреса твоих микросервисов, если они динамически меняются в Kubernetes каждую минуту?

**Ответ Senior'а:** Ты не прописываешь IP-адреса Java-приложений в конфиг Prometheus. Ты настраиваешь интеграцию с **Service Discovery** (например, с Kubernetes API или Consul/Eureka). Prometheus сам подписывается на события Kubernetes. Когда поднимается новый под твоего `order-service`, Kubernetes сообщает об этом Prometheus'у, и тот автоматически начинает ходить по новому IP-адресу на эндпоинт `/actuator/prometheus`.

### 3. Исключение из правил: Pushgateway (Для Spring Batch)

Это любимый вопрос-ловушка архитекторов: _"У нас есть Spring Batch джоба (скрипт). Она просыпается ночью, за 3 секунды пересчитывает скидки в базе, генерирует метрики и выключается. Prometheus собирает метрики раз в 15 секунд. Как мониторить такую джобу?"_

**Ответ:** Prometheus просто не успеет ее опросить. Для таких **короткоживущих задач (Short-lived jobs)** Pull-модель не работает. Разработчик должен использовать **Pushgateway** — это специальный промежуточный кэш-сервер от создателей Prometheus. Твоя Java-джоба перед самым завершением сама пушит (отправляет) свои метрики в Pushgateway. А уже оттуда Prometheus не спеша заберет их при следующем цикле опроса.

### 4. Золотые метрики JVM (Что именно искать при сбоях)

Ты не должен знать весь конфиг Prometheus, но ты обязан знать, какие метрики отдает Spring Boot Actuator "из коробки" для расследования инцидентов.

Если приложение тормозит, Senior смотрит на эти три графика (они генерируются автоматически):

1. **`jvm_memory_used_bytes` (Heap):** Если график имеет форму ровной "пилы" — всё отлично (GC работает). Если пила упирается в потолок и не падает — у тебя утечка памяти (Memory Leak), скоро будет падение.
    
2. **`jvm_gc_pause_seconds` (Паузы сборщика мусора):** Если GC останавливает приложение (Stop-The-World) на 2 секунды, твои HTTP-запросы будут отваливаться по таймауту. Этот график показывает, виноват ли твой код или настройки JVM.
    
3. **`hikaricp_connections_active` (Пул БД):** Если активных коннектов 20, а размер пула 20, значит, приложению не хватает соединений с базой данных (Thread Starvation). Проблема не в процессоре, а в медленных SQL-запросах (или кто-то забыл закрыть транзакцию).
