Паттерн **Builder (Строитель)** — это классический порождающий паттерн, который решает одну из самых раздражающих проблем в Java: создание объектов с большим количеством полей.

На собеседованиях этот паттерн любят, потому что он напрямую связан с концепцией **Иммутабельности (Неизменяемости)** — важнейшего принципа для многопоточных и надежных систем.

Давай разберем, какую боль он лечит, и как это работает на проде.

### 1. Боль №1: Телескопический конструктор (Telescoping Constructor)

Представь класс `User`, у которого есть 3 обязательных поля и 5 необязательных. Если писать на чистой Java, разработчики обычно создают кучу конструкторов под разные случаи:

Java

```
public class User {
    public User(String login, String email, String password) { ... }
    public User(String login, String email, String password, String phone) { ... }
    public User(String login, String email, String password, String phone, int age) { ... }
}
```

**Почему это провал:** Когда ты видишь в коде вызов `new User("admin", "admin@mail", "1234", null, 25, true, null)`, ты понятия не имеешь, что означают эти `null` и `true`, не проваливаясь внутрь конструктора. А если подряд идут три поля типа `String`, перепутать местами имя и фамилию — проще простого. Компилятор ошибку не выдаст.

### 2. Боль №2: Паттерн JavaBean (Геттеры и Сеттеры)

Чтобы не писать страшные конструкторы, джуниоры используют пустой конструктор и сеттеры:

Java

```
User user = new User();
user.setLogin("admin");
user.setEmail("admin@mail");
user.setActive(true);
```

**Почему за это ругают Senior'ы:**

1. **Потеря Иммутабельности:** Объект можно изменить в любой момент времени из любого потока. Это источник самых трудноуловимых багов (Race Conditions).
    
2. **Неконсистентное состояние:** Между вызовом `new User()` и последним сеттером объект находится в невалидном состоянии. Если в этот момент другой поток схватит этот объект и попытается сохранить в БД, он сохранит "полупустого" юзера.
    

### 3. Решение: Паттерн Builder

Builder решает обе проблемы: он дает **читаемость** сеттеров и **безопасность** конструкторов. Объект создается пошагово в цепочке вызовов, но физически рождается только в самом конце, при вызове метода `build()`.

**Как это выглядит на проде с Lombok:** Никто в здравом уме не пишет классы-билдеры руками (это заняло бы 50-100 строк шаблонного кода на каждый класс). Все используют аннотацию `@Builder` из библиотеки Lombok.

Java

```
@Builder
@Getter // Только геттеры! Никаких сеттеров, объект должен быть иммутабельным (или используем @Value)
public class User {
    private final String login;
    private final String email;
    private final String password;
    private final String phone;
    private final int age;
    private final boolean isActive;
}
```

**Использование в бизнес-логике:**

Java

```
User user = User.builder()
                .login("admin")
                .email("admin@mail.com")
                .password("secure123")
                .age(25)
                .isActive(true)
                // phone мы просто не указываем, он будет null
                .build();
```

- **Идеальная читаемость:** Код самодокументируется. Невозможно перепутать поля.
    
- **Иммутабельность:** Все поля `final`. Объект создается целиком в методе `build()`.
    

### 4. Фишки Lombok @Builder для собеседования (Уровень Senior)

Интервьюер может спросить: _"А как в Lombok Builder задать значения по умолчанию?"_ или _"Как удобно добавлять элементы в списки?"_.

**Значения по умолчанию (`@Builder.Default`):** Если просто написать `private boolean isActive = true;`, то Builder проигнорирует это значение (оно станет `false`). Нужно явно указать аннотацию:

Java

```
@Builder.Default
private boolean isActive = true;
```

**Работа с коллекциями (`@Singular`):** Часто у объекта есть список (например, роли). В классическом варианте пришлось бы заранее создавать `List`, заполнять его и передавать в билдер. Lombok делает это элегантно:

Java

```
@Builder
public class User {
    private String login;
    
    @Singular // Магия здесь!
    private List<String> roles;
}

// В коде:
User user = User.builder()
                .login("admin")
                .role("ADMIN") // Добавляем по одному! Lombok сам создаст список.
                .role("MANAGER")
                .build();
```

> **Архитектурный вывод:** Builder — это стандарт индустрии для создания DTO (Data Transfer Objects), сущностей для тестов и иммутабельных бизнес-объектов. В связке с Lombok он делает код чистым, безопасным и защищенным от ошибок человеческого фактора.
