
Отличное решение — структурировать знания. На собеседованиях часто просят не просто перечислить методы, но и объяснить разницу между похожими (например, `map` и `flatMap`, или `findFirst` и `findAny`).

Чтобы твой ответ звучал на уровне Senior, я разделю промежуточные операции на **Stateless** (без состояния, работают быстро) и **Stateful** (с состоянием, требуют памяти), а терминальные — на обычные и **Short-circuiting** (короткое замыкание, могут прервать стрим досрочно).

### I. Промежуточные операции (Intermediate)

_Возвращают новый `Stream`. Ленивые — не выполняются до вызова терминальной операции._

**Без состояния (Stateless) — работают с каждым элементом изолированно:**

- **`filter(Predicate)`** — Оставляет только те элементы, которые удовлетворяют условию (возвращают `true`).
    
- **`map(Function)`** — Преобразует каждый элемент в другой объект (связь 1 к 1). _Например, из объекта `User` достать его `String name`._
    
- **`flatMap(Function)`** — **(Любимый вопрос на собесах)**. В отличие от `map`, он преобразует один элемент в _множество_ (возвращает Stream) и "сплющивает" (объединяет) все получившиеся стримы в один. _Идеально, чтобы из `List<User>` (где у каждого юзера есть `List<Role>`) получить плоский `Stream<Role>` всех ролей всех юзеров._
    
- **`peek(Consumer)`** — Позволяет выполнить действие над элементом, не меняя его.
    
    > _Ловушка:_ Никогда не используй его для изменения данных (side-effects). Он создан **исключительно для дебага и логирования** (например, `peek(System.out::println)`). Во многих случаях JVM может просто проигнорировать вызов `peek`, если сочтет его ненужным для оптимизации.
    

**С состоянием (Stateful) — требуют накопления элементов в памяти:**

- **`distinct()`** — Убирает дубликаты. Под капотом использует `equals()` и `hashCode()`. Если стрим бесконечный, эта операция сожрет всю память.
    
- **`sorted() / sorted(Comparator)`** — Сортирует элементы. Жесткое узкое горлышко производительности: стрим вынужден "заморозиться", дождаться всех элементов, отсортировать их, и только потом отдать дальше.
    
- **`limit(long n)`** — Оставляет только первые `n` элементов. _(Является Short-circuiting — обрывает стрим после достижения лимита)._
    
- **`skip(long n)`** — Пропускает (отбрасывает) первые `n` элементов.
    

### II. Терминальные операции (Terminal)

_Запускают весь конвейер на выполнение. Возвращают конкретный результат или `void`._

**Обычные (обрабатывают все элементы):**

- **`collect(Collector)`** — Самый частый метод. Собирает результат в коллекцию (`toList`, `toSet`), группирует в мапу (`groupingBy`) или склеивает в строку (`joining`).
    
- **`reduce(...)`** — **(Спросят на Senior'а)**. Выполняет "свертку" стрима. Берет элементы по два и объединяет их по заданному правилу в один, пока не останется единственный результат. _Классика: подсчет суммы всех чисел или конкатенация сложной строки._
    
- **`forEach(Consumer)`** — Выполняет действие для каждого элемента (например, сохранение в БД).
    
    > _Нюанс:_ В `parallelStream()` метод `forEach` **не гарантирует порядок** выполнения. Если порядок важен, нужно использовать **`forEachOrdered()`**.
    
- **`count()`** — Возвращает количество элементов в стриме (тип `long`).
    
- **`min(Comparator) / max(Comparator)`** — Находит минимальный/максимальный элемент, возвращает `Optional`.
    

**Short-circuiting (Короткое замыкание — могут остановить стрим досрочно):**

- **`anyMatch(Predicate)`** — Возвращает `true`, если _хотя бы один_ элемент подходит под условие. Останавливается на первом же совпадении.
    
- **`allMatch(Predicate)`** — Возвращает `true`, если _абсолютно все_ элементы подходят. Останавливается на первом же несовпадении (вернув `false`).
    
- **`noneMatch(Predicate)`** — Возвращает `true`, если _ни один_ элемент не подошел.
    
- **`findFirst()`** — Возвращает первый элемент стрима (завернутый в `Optional`). Останавливает конвейер мгновенно.
    
- **`findAny()`** — Возвращает любой элемент стрима.
    
    > _Вопрос с подвохом:_ Зачем нужен `findAny`, если есть `findFirst`? В обычном стриме они работают одинаково. Но в **`parallelStream()`** `findFirst` заставит потоки синхронизироваться, чтобы отдать именно исторически "первый" элемент. `findAny` отдаст тот, который какой-либо из потоков вычислит быстрее всего, что работает в разы эффективнее.
