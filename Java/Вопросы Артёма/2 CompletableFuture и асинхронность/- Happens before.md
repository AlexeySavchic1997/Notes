
### 1. Program Order Rule (Правило порядка программы)

Каждое действие в рамках одного потока happens-before любого другого действия в этом же потоке, которое идет _следом_ по тексту программы.

- _Пример:_ Если ты сначала написал `int x = 1;`, а потом `int y = 2;`, то для этого потока `x = 1` происходит раньше, чем `y = 2`.
    

### 2. Monitor Lock Rule (Правило монитора / `synchronized`)

Разблокировка (unlock) монитора в одном потоке **happens-before** любой последующей блокировки (lock) этого же монитора в _другом_ потоке.

- _Что это дает на практике:_ Всё, что было изменено внутри блока `synchronized` одним потоком, гарантированно видно другому потоку, который зашел в этот же `synchronized` блок позже.
    

### 3. Volatile Variable Rule (Правило volatile полей)

Запись в переменную `volatile` **happens-before** любого последующего чтения из _этой же_ переменной.

- _Что это дает:_ `volatile` гарантирует не только атомарность (не CAS речь о иной атомарности)записи ссылок/примитивов, но и то, что изменения сразу сбрасываются из кэша ядра в общую память (RAM), а другие потоки гарантированно увидят актуальное значение.
    

### 4. Thread Start Rule (Правило запуска потока)

Вызов метода `thread.start()` в потоке A **happens-before** любых действий в запускаемом потоке.

- _Что это дает:_ Всё, что ты записал в переменные _до_ вызова `thread.start()`, будет отлично видно внутри нового потока.
    

### 5. Thread Termination Rule (Правило завершения потока)

Любое действие в потоке **happens-before** того момента, когда другой поток успешно обнаружил, что этот поток завершился (`thread.join()` вернул результат или `isAlive()` стал `false`).
