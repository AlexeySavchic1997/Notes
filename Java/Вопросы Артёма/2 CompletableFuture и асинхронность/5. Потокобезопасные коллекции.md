5.1 Синхронизированные
Тема потокобезопасных коллекций — это абсолютная классика на собеседованиях. Эволюцию коллекций в Java можно разделить на два больших лагеря: **Synchronized** (старый подход) и **Concurrent** (современный подход).

Поскольку ты просил начать с синхронизированных, давай разберем этот «старый мир», как он работает и почему на смену ему пришел `java.util.concurrent`.

## 1. Динозавры Java: Vector и Hashtable

В самых первых версиях Java (1.0) разработчики решили проблему потокобезопасности максимально в лоб. Они создали классы `Vector` (аналог `ArrayList`), `Hashtable` (аналог `HashMap`) и `Stack`.

**Как они работают?** Всё предельно просто. Абсолютно каждый метод внутри этих классов помечен ключевым словом `synchronized`.

Java

```
public synchronized boolean add(E e) {
    // логика добавления
}

public synchronized E get(int index) {
    // логика чтения
}
```

**Почему их больше не используют?** Потому что монитором (мьютексом) выступает сам объект коллекции (`this`). Это означает **глобальную блокировку (Coarse-grained locking)**. Если один поток вызвал метод `get()`, чтобы прочитать элемент, все остальные потоки (даже те, которые тоже хотят просто прочитать данные) будут заблокированы и выстроятся в очередь. В высоконагруженных многопоточных приложениях это превращается в чудовищное «бутылочное горлышко» (bottleneck).

## 2. Шаг вперед: Обёртки Collections.synchronized*

В Java 1.2 появился Java Collections Framework (`ArrayList`, `HashMap` и т.д.), которые по умолчанию были не потокобезопасными. Но разработчики добавили утилитные методы-обертки:

Java

```
List<String> list = new ArrayList<>();
List<String> syncList = Collections.synchronizedList(list);

Map<String, String> syncMap = Collections.synchronizedMap(new HashMap<>());
```

**Как это работает "под капотом"?** Здесь используется паттерн **Decorator**. Метод создает класс-обертку. Внутри этой обертки хранится ссылка на твою оригинальную коллекцию и специальный объект `mutex` (по умолчанию это сама обертка `this`).

Java

```
// Упрощенный код из исходников Java
public void add(int index, E element) {
    synchronized (mutex) {
        list.add(index, element);
    }
}
```

По сути, это то же самое, что и `Vector`. Глобальная блокировка осталась. Но этот подход был чуть гибче, так как позволял сделать потокобезопасной любую коллекцию.

## 3. Любимые вопросы-ловушки на собеседовании

Интервьюеры любят проверять, понимаешь ли ты подводные камни синхронизированных коллекций. Вот два главных капкана:

### Капкан №1: Итерация и ConcurrentModificationException

Даже если коллекция создана через `Collections.synchronizedList()`, обход этой коллекции через `for-each` (или итератор) **не является потокобезопасным**.

Если один поток перебирает элементы, а второй в это время удаляет или добавляет элемент, первый поток упадет с ошибкой `ConcurrentModificationException` (итератор реализован по принципу fail-fast).

**Как правильно (и это нужно озвучить на интервью):** При итерации по синхронизированной коллекции ты **обязан** вручную заблокировать ее на всё время обхода:

Java

```
List<String> syncList = Collections.synchronizedList(new ArrayList<>());

// Ручная блокировка ОБЯЗАТЕЛЬНА при итерации!
synchronized (syncList) {
    for (String s : syncList) {
        System.out.println(s);
    }
}
```

### Капкан №2: Составные операции (Check-then-act)

Синхронизированные коллекции гарантируют атомарность только **одиночных** вызовов. Если тебе нужно сделать логику «проверь и добавь», синхронизированная коллекция не спасет от состояния гонки (Race Condition).

Java

```
// ПЛОХО: Два потока могут одновременно пройти проверку contains
if (!syncList.contains("Apple")) {
    syncList.add("Apple"); 
}

// ПРАВИЛЬНО: Опять нужна внешняя ручная блокировка
synchronized (syncList) {
    if (!syncList.contains("Apple")) {
        syncList.add("Apple");
    }
}
```

**Резюме по синхронизированным коллекциям:** Они работают через единую глобальную блокировку. Из-за этого они невероятно медленные в конкурентной среде, так как полностью убивают параллелизм. Сегодня они считаются легаси-подходом.
