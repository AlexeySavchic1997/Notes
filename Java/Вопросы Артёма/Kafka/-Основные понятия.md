Apache Kafka — это один из самых популярных инструментов в современной архитектуре. И первое, что нужно уяснить для собеседования: **Kafka — это не классическая очередь сообщений (Message Queue), это распределенный журнал событий (Distributed Commit Log).**

Классическая очередь (как RabbitMQ) работает по принципу: прочитал сообщение — оно удалилось. Kafka работает как файл логов: сообщения пишутся на жесткий диск друг за другом и **не удаляются после прочтения** (они хранятся заданное время, например, 7 дней).

Давай разберем базовый словарь и топ-3 стартовых вопроса на собеседованиях.

## 1. Базовые понятия (Словарь Kafka)

- **Message (Сообщение / Событие):** Базовая единица данных (обычно массив байтов, часто JSON или Avro). Состоит из ключа, значения, таймстемпа и заголовков.
    
- **Topic (Топик):** Логическое имя для потока сообщений. Аналог «Таблицы» в базе данных или «Папки» на диске. Продюсеры пишут в топик, консюмеры читают из него.
    
- **Partition (Партиция):** Это самое важное понятие для понимания масштабируемости! Топик физически разбивается на несколько партиций. Каждая партиция — это упорядоченный, неизменяемый файл на диске (лог).
    
- **Offset (Смещение):** Порядковый номер сообщения внутри конкретной партиции. Он строго возрастает (0, 1, 2, 3...). По оффсету консюмер понимает, какие сообщения он уже прочитал, а какие еще нет.
    
- **Producer (Продюсер):** Приложение, которое пишет данные в Kafka.
    
- **Consumer (Консюмер):** Приложение, которое читает данные из Kafka.
    
- **Consumer Group (Группа консюмеров):** Набор консюмеров, которые объединяются для совместного (параллельного) чтения данных из одного топика.
    
- **Broker (Брокер):** Один сервер (инстанс) Kafka. Кластер Kafka состоит из нескольких брокеров.
