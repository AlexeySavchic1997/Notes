## Сводная таблица отличий

| **Возможность**             | **Future (Java 5)**                                | **CompletableFuture (Java 8)**                           |
| --------------------------- | -------------------------------------------------- | -------------------------------------------------------- |
| **Коллбэки (Non-blocking)** | ❌ Нет. Нужно блокировать поток через `get()`.      | ✅ Есть. Методы `thenApply`, `thenAccept`.                |
| **Цепочки вызовов**         | ❌ Нельзя передать результат одной Future в другую. | ✅ Можно. Метод `thenCompose`.                            |
| **Комбинирование**          | ❌ Сложно. Нужно вызывать `get()` у обоих и ждать.  | ✅ Легко. Методы `thenCombine`, `allOf`, `anyOf`.         |
| **Обработка ошибок**        | ❌ Только `try-catch` вокруг метода `get()`.        | ✅ Функциональная (`exceptionally`, `handle`).            |
| **Ручное завершение**       | ❌ Только чтение. Нельзя задать результат руками.   | ✅ Метод `complete(value)` или `completeExceptionally()`. |
| **Наследуемые интерфейсы**  | `Future`                                           | `Future`, `CompletionStage`                              |
## 4 суперсилы CompletableFuture (Что нужно рассказать интервьюеру)

В Java 8 появился `CompletableFuture`. Его главная фишка в том, что он реализует интерфейс **`CompletionStage`** — контракт, который позволяет строить конвейеры (пайплайны) из задач.

### 1. Подписка вместо ожидания (Коллбэки)

Теперь тебе не нужно вызывать блокирующий `get()`. Ты можешь просто сказать, что нужно сделать, когда данные придут.

```Java
CompletableFuture.supplyAsync(() -> doHeavyNetworkCall())
    .thenApply(String::toUpperCase) // Когда скачается, переведи в верхний регистр
    .thenAccept(result -> System.out.println("Результат: " + result)); // И выведи на экран

System.out.println("Этот код выполнится сразу, мы ничего не ждем!");
```

### 2. Цепочки и Комбинирование (Chaining & Combining)

Представь, что тебе нужно сделать запрос к базе данных, а затем с этими данными сделать запрос в сторонний API. В случае с `Future` это был бы ад из вложенных вызовов. С `CompletableFuture` это делается элегантно:

- **`thenCompose`** — когда результат первой задачи нужен для запуска второй.
    
- **`thenCombine`** — когда нужно запустить две задачи параллельно, дождаться обеих и склеить результат.
    

Java

```
CompletableFuture<User> userFuture = getUserByIdAsync(1);
CompletableFuture<Account> accountFuture = getAccountForUserAsync(1);

// Ждем выполнения ОБЕИХ независимых задач параллельно
userFuture.thenCombine(accountFuture, (user, account) -> {
    return new UserDto(user.getName(), account.getBalance());
});
```

### 3. Элегантная обработка исключений

Если в обычном `Future` внутри потока падал Exception, ты узнавал об этом только тогда, когда делал `get()`, и он оборачивался в жуткий `ExecutionException`. В `CompletableFuture` исключения передаются по цепочке, и ты можешь обработать их в стиле функционального программирования:

```Java
CompletableFuture.supplyAsync(() -> {
        if (Math.random() > 0.5) throw new RuntimeException("Упала база!");
        return "Успех";
    })
    .exceptionally(ex -> {
        System.err.println("Ошибка: " + ex.getMessage());
        return "Дефолтное значение"; // Возвращаем fallback-ответ
    })
    .thenAccept(System.out::println);
```

### 4. Ручное завершение (Manual Completion)

Классический `Future` — это read-only объект с точки зрения того, кто его ждет. Фоновый поток должен сам завершить свою задачу. `CompletableFuture` (как понятно из названия) может быть завершен вручную из любого места твоего приложения. Это невероятно полезно при интеграции старых асинхронных библиотек или написании своих кэшей.


```Java
CompletableFuture<String> future = new CompletableFuture<>();

// В другом потоке или при получении веб-хука:
future.complete("Я решил завершить эту задачу прямо сейчас!");
// или 
future.completeExceptionally(new RuntimeException("Отмена операции"));
```
