В Kubernetes есть десятки различных сущностей, но от Java-разработчика не требуют знать их все (это работа DevOps). Для успешного прохождения секции по K8s на Middle/Senior тебе нужно уверенно ориентироваться в **базовой десятке**.

Я разобью их на 4 логические группы, чтобы они легко уложились в голове.

### Группа 1. Рабочие нагрузки (Workloads) — _Кто выполняет код?_

Это те сущности, которые непосредственно запускают твои Docker-контейнеры.

1. **Pod (Под / Стручок)**
    
    - **Что это:** Минимальная, неделимая единица K8s. Обертка вокруг одного или нескольких контейнеров, которые делят общий IP-адрес и локальный диск.
        
    - **На собеседовании:** Важно помнить, что Поды смертны, их IP меняется при рестарте, и вручную (без менеджеров ниже) их никто на проде не запускает.
        
2. **Deployment (Развертывание)**
    
    - **Что это:** Менеджер для **Stateless** приложений (твой Spring Boot микросервис).
        
    - **Зачем нужен:** Гарантирует, что работает заданное количество Подов (самолечение при падении узлов). Управляет бесшовным обновлением версий (Rolling Update), чтобы при релизе не было простоя (zero-downtime).
        
3. **StatefulSet (Набор с состоянием)**
    
    - **Что это:** Менеджер для **Stateful** приложений (PostgreSQL, Kafka, Redis, Elasticsearch).
        
    - **Зачем нужен:** Дает Подам строгие неизменные имена (`db-0`, `db-1`), запускает их строго по очереди и, самое главное, намертво привязывает к ним их физические диски. При рестарте Пода данные не теряются.
        
4. **Job / CronJob (Задача / Задача по расписанию)**
    
    - **Что это:** Запуск контейнера, который должен выполнить работу и **завершиться** (выйти с кодом 0).
        
    - **Когда использовать:** В отличие от Deployment (который работает вечно как веб-сервер), Job используют для разовых задач. Например: накатить миграции базы данных (Flyway/Liquibase) перед запуском основного приложения, сгенерировать ночной отчет, сделать бэкап.
        

### Группа 2. Сеть (Networking) — _Как до них достучаться?_

Поды постоянно умирают и меняют IP. Эти сущности решают проблему связи.

5. **Service (Сервис)**
    
    - **Что это:** Внутренний балансировщик нагрузки кластера.
        
    - **Зачем нужен:** Дает группе Подов единый, постоянный IP-адрес и внутреннее DNS-имя (например, `http://payment-service`). Микросервисы общаются друг с другом **только через Services**, никогда не обращаясь к Подам напрямую.
        
    - _Три типа на заметку:_ `ClusterIP` (доступен только внутри кластера — по умолчанию), `NodePort` (открывает порт наружу на каждом сервере), `LoadBalancer` (заказывает внешний IP у облачного провайдера).
        
6. **Ingress (Входной шлюз)**
    
    - **Что это:** Маршрутизатор (API Gateway) для **внешнего** трафика.
        
    - **Зачем нужен:** Service работает внутри кластера. А как браузеру из интернета достучаться до приложения? Ingress принимает весь внешний HTTP/HTTPS трафик на 80/443 порты и раскидывает его по нужным внутренним Service в зависимости от URL.
        
    - _Пример:_ Если запрос пришел на `[mycompany.com/api/users](https://mycompany.com/api/users)` -> Ingress отправит его в `user-service`. Если на `[mycompany.com/api/orders](https://mycompany.com/api/orders)` -> в `order-service`.
        

### Группа 3. Конфигурация и Хранение — _Где лежат данные?_

7. **ConfigMap (Карта конфигурации)**
    
    - **Что это:** Словарь с несекретными настройками (URL баз данных, уровни логирования, `application-prod.yml`).
        
    - **Зачем нужен:** Чтобы не зашивать настройки в Docker-образ. Передается в Pod как переменные окружения (ENV) или как смонтированные файлы.
        
8. **Secret (Секрет)**
    
    - **Что это:** То же самое, что ConfigMap, но для паролей, токенов и сертификатов.
        
    - **В чем разница:** Значения в Secret хранятся в кодировке Base64 (а могут быть и зашифрованы на диске). K8s старается держать их только в оперативной памяти (tmpfs), чтобы они не попали на жесткие диски серверов.
        
9. **PersistentVolumeClaim (PVC — Запрос постоянного тома)**
    
    - **Что это:** Заявка от разработчика на выделение места на диске.
        
    - **Как работает:** Разработчик пишет в YAML: _"Мне нужен диск на 50 ГБ"_. K8s видит эту заявку (PVC), находит свободный физический диск (PersistentVolume) и связывает их. Разработчику не нужно знать, хранится ли это на Amazon AWS, сетевом хранилище NFS или локальном SSD сервера.
        

### Группа 4. Организация

10. **Namespace (Пространство имен)**
    
    - **Что это:** Виртуальный кластер внутри одного большого физического кластера K8s.
        
    - **Зачем нужен:** Представь, что у компании всего один дорогой дата-центр. Чтобы разработчики не мешали друг другу, создают неймспейсы: `dev`, `test`, `prod`. Сущности из одного неймспейса по умолчанию изолированы от других. Если ты удалишь Pod `my-app` в `dev`, продакшен не пострадает.
        

**Резюме для собеседования:** Если ты понимаешь, что **Deployment** запускает твой код, **Service** дает ему внутреннее имя, **Ingress** пускает к нему трафик из интернета, а **ConfigMap/Secret** прокидывают настройки извне — ты знаешь Kubernetes лучше 80% кандидатов на мидла.
