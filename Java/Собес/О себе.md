For our workflow, we strictly followed **Git Flow**. We had a `main` branch for production and a `develop` branch for active work. Every new feature was developed in a separate `feature/` branch. ==Самая сложная задача==

"I can share a challenge related to the warehouse integration for our retail perfume and cosmetics chain.

**(Situation):** Every day, my microservice had to process a huge XML file — several gigabytes in size — containing product and inventory data from perfume suppliers. My job was to read the file, validate the data, and send it to the order management service via Kafka.

**(Task):** I faced two main challenges. First, I couldn't load the whole file into RAM because it would immediately cause an `OutOfMemoryError`. Second, the validation rules for different cosmetic brands were very complex.

**(Action):** At first, I used **StAX** because it reads files streamingly without using much memory. However, writing complex validation with StAX created a huge mess of `if/else` statements. So, I decided to rewrite the code using **Jackson XML with `MappingIterator`**. This tool reads the file one `<product>` at a time and maps it directly into a Java POJO, which keeps memory usage low. After getting the POJO, I simply used **Hibernate Validator** annotations for the business checks. Finally, I collected valid products in batches of 500 to send to Kafka, and sent the invalid ones to a Dead Letter Queue (DLQ).

**(Result):** This change was a huge success. It removed about 800 lines of complex code. Memory usage stayed perfectly low and stable. Best of all, the code became very easy to support: when business rules changed a month later, it took me only 15 minutes to update the annotations without touching the parser logic at all."
