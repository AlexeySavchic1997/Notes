### 🌱 Spring Framework: IoC, DI & Basics

#### ❓ Question 1: Inversion of Control (IoC)

**Interviewer:** _"Can you explain what Inversion of Control (IoC) is in Spring?"_ _(Можете объяснить, что такое Инверсия Контроля в Spring?)_

**Your Answer (B1/B2):**

> "Inversion of Control means we give the control of creating objects to the Spring Framework. Instead of manually creating objects using the `new` keyword, the **Spring IoC Container** creates, configures, and manages these objects (which we call Beans) for us."

#### ❓ Question 2: Dependency Injection (DI)

**Interviewer:** _"What is Dependency Injection (DI) and how is it different from IoC?"_ _(Что такое Внедрение Зависимостей и чем оно отличается от IoC?)_

**Your Answer (B1/B2):**

> "IoC is the general concept, and **Dependency Injection is the actual pattern** used to implement it. DI means that Spring automatically 'injects' the required dependencies into our classes. This makes our code loosely coupled and much easier to test."

#### ❓ Question 3: Constructor vs Field Injection

**Interviewer:** _"Why is Constructor Injection recommended over Field Injection (using `@Autowired` on fields)?"_ _(Почему внедрение через конструктор рекомендуется чаще, чем внедрение через поле?)_

**Your Answer (B1/B2):**

> "Constructor injection is better for two reasons. First, it allows us to make our fields `final`, which makes the class immutable and thread-safe. Second, it makes **unit testing much easier** because we can pass mock objects directly into the constructor without using Spring context."

#### ❓ Question 4: Bean Scopes

**Interviewer:** _"What is a Spring Bean, and what is its default scope?"_ _(Что такое Spring Bean и какова его область видимости по умолчанию?)_

**Your Answer (B1/B2):**

> "A Bean is simply a Java object managed by the Spring IoC container. The default scope is **Singleton**. This means Spring creates only one single instance of this object and uses it everywhere in the application. Another popular scope is **Prototype**, which creates a new instance every time."

### 🐘 SQL Basics: Operators & Filtering

#### ❓ Question 5: IN vs BETWEEN Operators

**Interviewer:** _"In SQL, what is the difference between the `IN` and `BETWEEN` operators?"_ _(В чем разница между операторами IN и BETWEEN?)_

**Your Answer (B1/B2):**

> "The `IN` operator checks if a value matches any value in a specific list (for example, `status IN ('NEW', 'SENT')`). The `BETWEEN` operator checks if a value falls within a specific range, for example, dates or numbers (like `age BETWEEN 18 AND 30`). It includes both the start and the end values."

#### ❓ Question 6: The LIKE Operator and Wildcards

**Interviewer:** _"How does the `LIKE` operator work, and what do the `%` and `_` wildcards mean?"_ _(Как работает оператор LIKE и что значат символы `%` и `_`?)_

**Your Answer (B1/B2):**

> "The `LIKE` operator is used to search for a specific text pattern in a column. The `%` sign represents **zero, one, or multiple characters** (e.g., `LIKE 'A%'` finds all names starting with A). The `_` sign represents **exactly one single character** (e.g., `LIKE '_at'` finds 'cat' or 'bat')."

#### ❓ Question 7: WHERE vs HAVING

**Interviewer:** _"Can you explain the difference between the `WHERE` and `HAVING` clauses?"_ _(Можете объяснить разницу между WHERE и HAVING? — Очень частый вопрос)_

**Your Answer (B1/B2):**

> "Both are used to filter data, but at different stages. The `WHERE` clause filters rows **before** they are grouped. The `HAVING` clause filters records **after** the `GROUP BY` operator has grouped them. Also, we cannot use aggregate functions like `COUNT()` or `SUM()` in `WHERE`, but we can use them in `HAVING`."

#### ❓ Question 8: INNER JOIN vs LEFT JOIN

**Interviewer:** _"What is the difference between an `INNER JOIN` and a `LEFT JOIN`?"_ _(В чем разница между INNER JOIN и LEFT JOIN?)_

**Your Answer (B1/B2):**

> "`INNER JOIN` returns only the rows that have a match in **both** tables. `LEFT JOIN` returns **all rows from the left table**, and the matched data from the right table. If there is no match in the right table, it simply returns `NULL` for those columns."
